# 推文结构公式

> 已验证的推文结构模板，写推文时直接套用。
> 随着数据复盘不断更新。

---

## 一、5种推文结构

### 1. 认知冲突型

```
[金句开头：一句断言打破常识]
[展开：为什么大多数人搞错了——用案例/数据/概念解构]
[收尾：金句 or 开放性问题]
```

**论证方式（任选1-2种）：**
- 概念解构：拿到一个常用词 → 追溯它本来的意思 → 检验在当前语境是否成立 → 否定或重新定义
- 反常识论证：先抛违反直觉的结论，再用逻辑推导证明它成立
- 数据断言：「我研究了XXX个案例，发现XX%的人都是因为……」

示例框架：
```
[一句断言，短、狠、准]
[大多数人以为 X]
但 [反直觉的事实 Y]
[一句话解释底层逻辑]
```

### 2. 数据+洞察型

```
[金句开头：一个出人意料的数据]
[展开：别人看到表面，你看到什么]
[收尾：更深一层的思考 or 开放性问题]
```

**数据使用原则：**
- 绝对数字 + 换算（不只说933条，还说"日均42条"）
- 数据要出人意料（普通的数据不如不放）
- 数据服务于故事（不是炫耀数据，是让观点更可信）
- 少用百分比，多用绝对值（"$25,000"比"25%收益"更有冲击力）

示例框架：
```
[数字] + [事实]
大多数人看到的是 [表面结论]
但真正值得关注的是 [深层洞察]
[一句话收尾]
```

### 3. 个人经历型

```
[金句开头：我做了什么/发生了什么]
[展开：具体的场景和细节——让人有画面感]
[收尾：一句话总结认知升级，不说教]
```

**关键技巧：**
- 自嘲转折：主动暴露自己的失败和愚蠢（「然后我就干了一个特别蠢的事儿」）消解权威感
- 先讲故事再讲道理：不要上来就总结，让人在故事里自己体会
- 语气是"朋友在分享经历"，不是"导师在传授经验"

示例框架：
```
[时间/场景] 我 [做了X]
[意外的结果 / 具体细节]
[一句话总结，不说教]
```

### 4. 金句型

```
[一句话，短、狠、准]
```

要求：不超过两句话，能独立传播，不需要上下文。

### 5. 提问型

```
[一个好问题——要能引发结论性好奇]
[给出一个反直觉的思考方向，但不给答案]
```

注意：不要超过推文总量的15%，太多显得没主见。

## 二、通用论证工具箱

写任何类型的推文都可以从这里选取论证方式，按效果排序：

| 论证方式 | 怎么用 | 适合场景 |
|----------|--------|----------|
| 概念解构 | 拿到常用词 → 追溯词源 → 检验逻辑 → 否定或重新定义 | 打破流行概念（如"赛道""精准人群"） |
| 数据断言 | 用精确数字（不是"很多"，是"240个"）支撑一个判断 | 需要说服力的观点 |
| A vs B对比 | 错误做法 vs 正确做法，让人秒懂差异 | 展示before/after、常见误区 |
| 案例论证 | 用真实的、具体的故事或案例作为证据 | 个人经历、他人故事 |
| 反常识论证 | 先抛违反直觉的结论，再用逻辑推导证明 | 认知冲突型内容 |

## 三、通用修辞策略

| 策略 | 说明 | 效果 |
|------|------|------|
| 先破后立 | 先解构一个流行概念/常见认知，再提出自己的替代框架 | 制造冲突 + 给出解法 |
| 层层递进 | 把一个问题分3-5层，逐层深入 | 让人觉得"越挖越深" |
| 自我解构 | 在建立权威的同时主动暴露自己的失败 | 消解爹味，增加真实感 |
| 口语化的逻辑表达 | 用聊天语气讲硬核逻辑 | 降低阅读门槛，拉近距离 |
| 强断言 | 极少使用"可能""也许"，直接给判断 | 制造信念感 |
| 多例证闭环一致 | 同一篇中用多个例子论证同一原理时，每个例子必须有相同的逻辑闭环结构（如：都有"行动→可验证的结果"）。如果一个例子有结果闭环而另一个没有，读者会感到前后割裂 | 避免论证断裂，保持说服力连贯 |

## 四、句式工具箱

写推文时可以直接套用的句式：

- **概念否定句**：「XXX这个词在概念本身上就不成立」
- **数据断言句**：「我研究了XXX个案例，最终发现XX%的人都是因为……」
- **反问确认句**：「这个事儿你真的敢这么干吗？」
- **阶段递进句**：「第一层……第二层……第三层……」
- **自嘲转折句**：「然后我就干了一个特别蠢的事儿……结果……」
- **强断言句**：「如果你不知道能不能做，那就是不能做」

## 五、出稿自检清单

每次写完推文、交给用户之前，**强制逐条过一遍**：

| # | 检查项 | 怎么查 |
|---|--------|--------|
| 1 | **事实性检查（最高优先级）** | 把文中所有事实性断言逐条列成表格，一条一条打勾验证。包括但不限于：数据是否准确、概念是否正确（如「管理费」是否存在）、比较对象是否公平（如税后 vs 税前）、金融/技术术语是否用对。**必须输出验证表格给用户看。** |
| 2 | **逻辑一致性检查** | 全文的核心论点是什么？每一个分论点是否都在支撑这个核心论点？有没有分论点跟核心论点矛盾或方向不一致？（例：核心论点是「他不行了」，但分论点在说他的优势——这就是逻辑mismatch） |
| 3 | **人名/称呼统一** | 全文扫一遍，同一个人的称呼是否前后一致？能用口语称呼（老巴、马斯克）的地方是不是还在用正式全名（沃伦·巴菲特、埃隆·马斯克）？ |
| 4 | **空洞词汇清除** | 搜一遍「结构性」「系统化」「有效」「赋能」「可持续」等禁用词，是不是又混进来了？ |
| 5 | **绝对化表述检查** | 有没有哪句话说得太满？该留余地的地方是不是缺了「几乎」「近乎」「大约」等修饰？ |
| 6 | **数据/单位核实** | 所有数字、百分比、倍数、年龄、日期是否准确？%和倍数有没有搞混？ |
| 7 | **禁用句式扫描** | 有没有出现「不是X，而是Y」及其变种？有没有「建议您」「综上所述」等AI句式？ |
| 8 | **长短句节奏** | 是不是全短句像念清单？读出来有没有人味？ |
