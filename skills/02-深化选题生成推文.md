# Skill: 深化选题生成推文

## 触发条件
用户说"写推文"、"生成推文"、"把这个选题写成推文"等

## 核心规则
- **先检索素材库，再动笔**（这是最重要的一条）
- 输出必须去"爹味儿"，像人说话
- Post ≤ 280字符（英文）或 ≤ 140字（中文）
- 每次生成 3 个版本，用不同结构

## 工作流程

### Step 1：检索素材库
按以下顺序检索：
1. `02-内容素材库/核心概念库/` — 相关理论框架
2. `02-内容素材库/金句库/` — 可复用的表达
3. `02-内容素材库/爆款推文库/` — 已验证的结构
4. `01-内容生产/已发布/` — 写过的类似内容

如果找到相关内容，告诉用户：
> 「你之前写过/存过相关内容：[简述]，要复用还是重新写？」

### Step 2：选择推文类型
根据选题特点，从以下类型中选择最合适的：

| 类型 | 适用场景 | 示例结构 |
|------|----------|----------|
| 认知冲突型 | 打破常识 | 反常识观点 → 为什么 → 金句收尾 |
| 数据+洞察型 | 有具体数字 | 数据事实 → 大多数人不知道 → 洞察 |
| 个人经历型 | 真实故事 | 我做了X → 结果Y → 学到Z |
| 金句型 | 一句话说透 | 短、狠、准，不超过两句 |
| 提问型 | 引发讨论 | 提出问题 → 给出反直觉的思考方向 |

### Step 3：生成 3 个版本
每个版本用不同的结构/角度，标注类型：
```
【版本A — 认知冲突型】
[推文内容]

【版本B — 数据+洞察型】
[推文内容]

【版本C — 个人经历型】
[推文内容]
```

### Step 4：自检
每个版本过一遍：
- [ ] 前两行能不能让人停下来？（不能 → 重写开头）
- [ ] 有没有爹味儿？（读出声，像不像人说的）
- [ ] 有没有张力？（对比/数字/悬念/冲突，至少2项）
- [ ] 结尾是不是"总结"式的？（是 → 换成金句或开放问题）
- [ ] 字数超标没？

### Step 5：保存
用户选定版本后，保存到 `01-内容生产/待发布/` 或 `01-内容生产/草稿箱/`

文件名格式：`[日期]-[主题关键词].md`

## 注意事项
- 不要一次生成超过3个版本，选择困难症会杀死效率
- 如果用户说"不对"或"不是这个感觉"，问清楚哪里不对，不要猜
- 推文不是文章，不需要"起承转合"，要快、准、狠
