# xc-write：深化选题生成推文（个人内容层）

> 属于个人内容层（`xc-*`）。**全程受根目录 `CLAUDE.md` 宪法约束**：事实优先法则、去爹味（禁用"不是 X 而是 Y"等句式）、人设保护、写作规范。

## 触发条件
用户说"写推文"、"生成推文"、"把这个选题写成推文"等。

## 核心规则
- **先检索素材库，再动笔**（最重要）。
- 输出去爹味，像人说话。
- **先写完整，再按平台精简**（X 会员长帖友好；小红书标题 ≤20 字、正文要短要跳）。
- 每次生成 3 个版本，用不同结构/类型。

## 工作流程

### Step 1：检索素材库（先复用再新写）
调用 `/xc-search` 的检索逻辑，顺序：①我的 `02-内容素材库/核心概念库 金句库 爆款推文库` ＋ `01-内容生产/已发布/` ②他的 `知识库/Skill知识包/content_内容创作方法论.md` ＋ `知识库/原子库/atoms.jsonl`。找到相关内容先告诉用户「你之前写过/存过：[简述]，要复用还是重新写？」

### Step 2：选择推文类型
| 类型 | 适用 | 结构 |
|------|------|------|
| 认知冲突型 | 打破常识 | 反常识断言 → 为什么 → 金句收尾 |
| 数据+洞察型 | 有具体数字 | 数据事实 → 大多数人不知道 → 洞察 |
| 个人经历型 | 真实故事 | 我做了 X → 结果 Y → 学到 Z |
| 金句型 | 一句话说透 | 短、狠、准，≤两句 |
| 提问型 | 引发讨论 | 好问题 → 反直觉的思考方向（不给答案，≤15%）|

### Step 3：生成 3 个版本
每个版本不同结构/角度，标注类型【版本 A — 认知冲突型】等。

### Step 4：自检（强制逐条过，详见 `03-方法论沉淀/推文结构公式.md` 的"出稿自检清单"）
- [ ] **事实性检查（最高优先级）**：所有事实断言列成表逐条打勾验证，**必须输出验证表格给用户**。不确定的去查（WebSearch），查不到标注"未证实"。
- [ ] **逻辑一致性**：每个分论点都支撑同一核心论点？观点能扛住"那你为什么不照做"的反问？
- [ ] 前两行能不能让人停下来？
- [ ] 有没有爹味？读出声像不像人说的？
- [ ] **禁用句式扫描**：有没有"不是 X 而是 Y"及变种？有没有"建议您""综上所述"？
- [ ] 空洞词清除（结构性/系统化/有效/赋能/可持续）。
- [ ] 张力 ≥2 项（对比/数字/悬念/冲突）？
- [ ] 结尾是不是"总结"式（是 → 换金句或开放问题）？
- [ ] 人名统一（口语称呼：马斯克/老巴，不要全名）。
- [ ] 字数/平台格式（小红书标题 ≤20 字）。

### Step 5：保存
用户选定后存到 `01-内容生产/待发布/` 或 `草稿箱/`，文件名 `[日期]-[主题关键词].md`。

## 注意事项
- 不要一次生成超过 3 个版本，选择困难症杀效率。
- 用户说"不对""不是这个感觉"，问清楚哪里不对，不要猜。
- post 要快、准、狠，不需要"起承转合"。

## 与 dbskill 衔接（局部打磨）
- 起小红书标题 → `/dbs-xhs-title`（75 公式），**出来后用 ≤20 字硬规砍一遍**。
- 开头不够抓人 → `/dbs-hook`（但避开"很多人问"式 AI 开头）。
- 出稿后查 AI 味 → `/dbs-ai-check`（叠加我的禁用句式）。
- 想要更系统的内容五维诊断 → `/dbs-content`。
- 概念要拆 → `/dbs-deconstruct`。
- 发布后 → `/xc-review` 记数据；爆款/金句 → `/xc-save` 入库。
